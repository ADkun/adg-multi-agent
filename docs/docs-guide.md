# 文档体系规范落地页

本页把写文档的规范写成**可执行的判据**：分层契约（谁能引用谁）、写作规范（写不写、怎么写）、状态陈述的四档分层（这句话能不能说成"实测"）、登记义务（新建模块要动哪两处）、以及文档自身怎么被检查。索引与"什么场景读哪篇"在 `docs/registry.md`，本页不重复。

## 1. 分层契约

每一层只回答一类问题；上层只做路由，知识一律在能被按需加载的那一层。

| 层 | 文件 | 回答什么 | 硬约束 |
|---|---|---|---|
| 入口 | `AGENTS.md`（仓库根，**存在**） | 项目一句话、命令、关键红线、模块地图、按改动选读的 Context Loading、Quality Gates | **只路由不做百科**；上限 200 行；任何能下沉的细节一律下沉 |
| 模块路由 | `<模块>/AGENTS.md` | 本模块的独立命令、模块特有红线、跨模块路由 | 只在三样信号里**至少占一样**时创建：有独立于根目录的命令 / 有模块特有红线 / 有跨模块路由要求。三样都没有就不要建（建了是噪音）。**禁止出现设计细节**，全部指针化 |
| 模块设计 | `<模块>/design.md` | 这个模块作为**对象**的类定义 | 六节固定：职责与边界（负责 + 逐条不负责）、依赖关系（依赖 / 被依赖 / 跨模块改动路由）、核心数据模型（对象形态 + 状态机 + 不变量）、对外接口（指向契约不复制）、非功能红线（每条带来源）、For Agents；外加测试与验证指向 `testing-guide.md` |
| 模块验证 | `<模块>/testing-guide.md` | 用例**从不变量穷举**，状态机给迁移矩阵全表 | 每条不变量编号对应一组用例；跨模块消费方必须写消费侧契约测试；禁止"测一下正常流程"这类从需求推导的模糊用例 |
| 事实台账 | `docs/evidence.md` | 哪些数字/结论量过、量到什么程度、哪些还没量 | 每条证据带**状态分层**（见第 3 节）；引用他人记载时必须写明来源 |
| 变更记录 | `docs/changelog.md` | 变了什么 | 一行一条、时间倒序；**只记"变了什么"，不记为什么**（为什么写在不变量旁的注释里就地说明） |
| 索引 | `docs/registry.md` | 有什么文档、什么场景读哪篇、哪些还是计划 | **禁止含正文** |

`docs/` 下文档 ≤ 5 篇时不建 `docs/_index.md`；`docs/registry.md` 本身就是这个目录的索引页。

## 2. 写作规范（可执行判据）

- **禁止流程叙述。** 不写"第一步/第二步/首先/然后"式章节：流程化描述会让执行者按模板注水。流程只允许作为**例外附录**出现，条件是存在异步时序、事务边界或跨介质切换，且**必须紧跟着指出它对应的可执行测试**。落到判据上：一条流程叙述若找不到对应测试，就删掉、改写成对象结构（状态机 + 迁移入口 + 不变量）。
- **不变量必须是无条件的否定式。** 写法是"禁止…"。若一条不变量需要加"当…时"才成立，说明对象切错了——回去重新切分，而不是给不变量加条件。
- **每条红线必须能指出对应测试，或标注"人工 review"。** 拿不出二者的红线不写；测试还没实现的，用例里写"未实现"并存档为缺口，不允许悄悄不留痕。
- **数据模型里只可出现他模块对象的引用句柄。** 本模块不负责其状态变更的对象，不得以实体形式出现在核心数据模型里——只能以"句柄/名称/路径"引用，用于声明协作关系。
- **引用不复制。** 接口、字段、流程一律指针化：写"见 `<路径>` 的哪一节"，不搬内容。能由代码或契约生成的内容（键集合、默认值、错误文本、行号）**必须生成**，不得手写后靠人工同步——手写的副本一定会漂移。
- **禁止无据形容词。** "本模块很重要/性能优越"这类无论据的表述不写；红线与坑必须能指出来源（事故 / 实测 / 压测 / 评审决定）。

## 3. 状态陈述的四档分层（本仓库特有，引用时必须保留）

同一句话，站在哪一档，说法完全不同。写文档时**逐句**给自己归档：

| 档 | 含义 | 允许的说法 | 典型的当下实例（示例，不替代 `docs/evidence.md`） |
|---|---|---|---|
| 源码级事实 | 读代码就能确认，不依赖运行环境 | "代码里 X 检查 Y" | `check-preset.mjs` 的常量名与分支、composition 的行结构 |
| 单元 / 静态检验 / 变异验证 | 有可重复执行的检查跑过 | "`node tools/check-preset.mjs` 退出码 0""插件的 `node --test test` 全绿" | 静态自检、插件单元测试与变异验证 |
| 真机实测（有日志为证） | 在真实机器上观测到，且能指出日志/转写 | "已实测：<现象>，证据见 `<日志路径>`" | 激活行、`step stage: nudged` 注入、真实挂载校验结果 |
| 未观测 | 没有证据 | "**未观测**：<问题>" + 量法 | "提醒是否让子代理更快收敛"（**注意**："新阶梯下的注入"原是本档示例，`docs/evidence.md` §9 已把它升到"真机实测"，用前先读 §9） |

规则：

- **引用他人记载的实测，必须写明来源并保留其状态档与时间戳**（"仓库 `README.md` 记载，真机实测，2026-09-25 01:37 重启后"、"`plugin/dsh-adg-token-budget/INSTALL.md` 记载"），**不得写成自己验证过**。自己没有跑过、没有读过那行日志，就不是实测档。
- **未观测不许写成实测**；同时不许把"未观测"写成"不可观测"——要写出量法。引用前先看 `docs/evidence.md` 的未观测清单：人向 `README.md` 与插件 `README.md` 里若干"未观测"条目已被 2026-09-25 的日志复核推翻（见该文件 §9），**处置权在人类**，发现冲突要报出来而不是按旧口径照抄。
- 已被撤销的旧口径必须标成**历史证据，不代表当前行为**。

## 4. 新模块登记义务

新建一个模块时，**同步**在两处各登记一行：

1. 根 `AGENTS.md` 的 **Project Map**（模块名 + 一句话职责 + "规则见 `<模块>/AGENTS.md`"）；
2. `docs/registry.md` 的文档索引表（该模块的 `AGENTS.md` / `design.md` / `testing-guide.md` 三行及其状态）。

**缺任一处即文档体系不完整**：只登记在根 `AGENTS.md`，按需文档找不到；只登记在 `docs/registry.md`，智能体读入口文档时根本不知道这个模块存在。登记只加在根文档里的模块地图即可，**不要在根 `AGENTS.md` 里展开它的设计**。

## 5. 文档自身的可执行检查：引用真实性

**引用真实性**指：文档里出现的每条命令、路径、链接、文档名都真的存在。腐化的入口文档比没有入口文档更糟——它会把智能体指向不存在的命令。

核对口径（三类引用，逐类核对；能自动化的部分不要靠人眼）：

```powershell
# 1) 文档名 / 路径引用：抽出被反引号包住、看起来像仓库内路径或文档名的串，逐一判存在
Select-String -Path .\AGENTS.md, .\docs\registry.md, .\docs\docs-guide.md, .\tools\AGENTS.md, .\tools\design.md, .\tools\testing-guide.md `
  -Pattern '`[A-Za-z0-9_.\-/]+\.(md|mjs|yml|js|ps1|sh)`' -AllMatches |
  ForEach-Object { $_.Matches.Value.Trim('`') } | Sort-Object -Unique |
  ForEach-Object { [pscustomobject]@{ Ref = $_; Exists = Test-Path -LiteralPath $_ } }
# 2) 命令引用：把文档里出现的 node / powershell 调用逐条真的敲一遍（`node tools/check-preset.mjs` 这类应当 exit 0）
#    插件的 `node --test test` 要 cd 到 plugin/dsh-adg-token-budget 下跑
# 3) 文档内小节引用：形如“见 `README.md`「某某」”的，先确认文件在，再确认那个小节标题真的在这份文件里
Select-String -Path .\README.md -Pattern '^#{1,4} ' | Select-Object -ExpandProperty Line
```

检索思路（不依赖 PowerShell 时的等价做法）：用 **grep 工具**搜文档里的路径引用并按唯一值去重，用 **glob 工具**确认哪些文件真的存在——注意 glob 的 `*` 会匹配任意深度、**根目录下的文件不在结果里**，要单独对仓库根列一次，避免"漏掉根级文件"这种假阴性。上面那三条命令与两个工具都要按"**先取出引用集合、再逐个判存在**"的顺序做，而不是抽查几条。

不存在的引用只有两种处理：改引用，或把目标补出来；**不许**留着一个指向未来的链接而不标明状态（计划中的路径一律在 `docs/registry.md` 标成"计划中（尚未创建）"）。
